## 2. Ежедневная модерация анкет

Всё мышкой, без SQL.

1. supabase.com → твой проект → **Table Editor** → таблица `people`.
2. Отфильтруй заявки: кнопка **Filter** → `status` → `is` → `pending`.
3. Открой строку (клик по ячейке или разворот строки) и проверь: ник похож на настоящий,
   Telegram — username, а не ссылка-приглашение и не телефон, в описании нет мусора и чужих данных.
4. Одобрить: ячейка `status` → `approved`. Отклонить: `rejected`. Удалить совсем: чекбокс строки → **Delete**.
5. Готово. На сайте анкета появится у всех при следующей загрузке страницы.

Что важно знать:

- `pending` виден **только автору** в его браузере, с бейджем «на проверке». Остальные его не видят вообще.
- После `approved` локальная копия у автора сама исчезнет и заменится общей записью.
- После `rejected` у автора бейдж сменится на «отклонена», и он сможет убрать заявку сам (корзина на карточке).
  Удаление строки тобой тоже работает: при следующей загрузке сайта локальная копия у автора исчезнет с уведомлением.
- Автор может отменить заявку сам: корзина на карточке «на проверке» удаляет строку в базе и освобождает ник.
  Исключение — заявки, отправленные до обновления с токенами: у их авторов кнопки нет, такие строки удаляешь ты.
- Автор может править заявку, пока она не одобрена: карандаш на карточке «на проверке» / «отклонена».
  После сохранения заявка снова `pending` — проверяй её заново. Ник автор поменять не может.
  После `approved` правки с сайта нет: человек пишет тебе, а ты правишь поля мышкой в Table Editor.
- Ник уникален: второй раз тот же ник не отправится (сайт покажет «ник занят»).
- Удалять строки можно смело: это не ломает сайт, просто человек исчезнет из каталога.

## 3. Контент: что можно мышкой, а что через код

Мышкой (Supabase): только анкеты — одобрить, отклонить, удалить, поправить поля.

Через код (правка файла + push): полезные сайты, чаты, клубы, организаторы, тексты FAQ и правил,
направления, интересы, внешний вид. Либо правишь сам по рецептам ниже, либо просишь AI-ассистента
(он читает `instructions_for_ai.md`), либо админа-разработчика.

Мини-рецепты (файл `app.js`, массивы в самом начале):

- **Чат:** в массив `chats` добавь строку вида
  `{ id: 'chat-mobile', group: 'campus', title: 'Мобильная разработка Ижевск', description: 'Чат направления.', url: 'https://t.me/...' },`
  `group` — id одной из групп в массиве `chatGroups` чуть выше (кампус, разработка, ветки, другие направления, боты, архив).
  Нужна новая группа — добавь её в `chatGroups`, и чипс фильтра появится сам.
  `tag` — короткое уточнение под названием без плашки («все части», «архив»), необязательно. `url: ''` оставит заглушку «Ссылку добавим позже».
- **Полезный сайт:** в массив `resources` добавь
  `{ id: 'mdn', group: 'tools', title: 'MDN', description: 'Справочник по вебу.', url: 'https://developer.mozilla.org' },`
  `group` — id блока из `resourceGroups` чуть выше (тренажёры, школа и кампус, переговорки, базы знаний, инструменты и карта).
  Посетители ссылки не добавляют: подборка общая и ведётся только через код.
- **Клуб и организаторы:** в массив `clubs` у клуба добавь
  `organizers: [{ name: 'Саша', nick: 'sasha', telegram: 'sasha' }]`.
  `nick` — ник Школы 21, `role` — роль текстом (например `ADM IZH`), оба необязательны.
  Тег организатора на сайте копируется кликом. Организатора ещё нет — `organizersSoon: true`.
- **FAQ и правила:** файл `index.html`, секция `id="page-rules"`. Вопрос — блок
  `<details class="faq-item"><summary>Вопрос?<svg class="icon"><use href="#i-chevron"/></svg></summary><p>Ответ.</p></details>`.
  Тексты уже заполнены — правь формулировки прямо в этих блоках.
- **Направление или интерес:** мало поменять `app.js` — нужно ещё обновить ограничение в базе.
  Это миграция, попроси AI дать готовый SQL и выполни его один раз в SQL Editor.

После любой правки кода — раздел 4.

### Дизайн: дракон, фон и цвета

Это инструкция на будущее: примеры ниже сами по себе ничего на сайте не меняют.
Сейчас оформление минимальное: без декоративных рамок, надписей над заголовками и футера; название кампуса видно только слева в шапке.
Верх первой вкладки — один заголовок со счётчиком, кнопка и маленький дракон рядом с ней. Скрытое сообщение результатов нужно экранным читалкам.
Карточки сайтов — без иконок и категорий, чаты — без значка Telegram, клубы — без иконок и вводного описания.
Функциональные значки кнопок, статусы заявок и обводка при переходе клавишей Tab остаются. В режиме высокой контрастности рамки нужны для доступности.
Сетки сайтов и чатов одинаковые: 4 колонки, до 1020px — 3, до 880px — 2, до 700px — 1; внутренний отступ карточек 18px.
Для оформления не нужно заходить в Supabase или менять анкеты.
Открой в редакторе папку `s21_izhevsk`, выбери файл слева, нажми **Ctrl+F** для поиска указанного текста и **Ctrl+S** после правки.
Перед экспериментом скопируй изменяемые файлы в отдельную папку **вне репозитория** — так их можно вернуть, не затронув остальные изменения.

| Что хочешь изменить | Где искать |

| Заголовок, счётчик и кнопка первой вкладки | `.hero` в `index.html` и `styles.css` |

#### 1. Дракон и компактный верхний блок

На первой вкладке один заголовок «Студенты кампуса» со счётчиком; рядом кнопка «Добавить анкету» и маленький дракон.
Отдельного заголовка «Студенты» ниже нет. Дракон занимает 64px на компьютере и 56px на экранах до 700px, без большой плашки.

Чтобы изменить верхний блок:

1. Открой `index.html`, нажми **Ctrl+F**, найди `id="people-heading"` — здесь меняется текст заголовка.
   Вложенный `span` с `id="people-count"` не удаляй и не дублируй: его значение обновляется автоматически.
2. Найди `class="hero"` — внутри заголовок и блок действий с кнопкой и рисунком. Атрибут `data-add-person` у кнопки не удаляй: он открывает форму.
3. В `styles.css` найди `.hero {` — `margin` задаёт внешние отступы, `gap` — расстояние между заголовком и действиями.
   Размер заголовка находится в `.hero h1, .page-intro h1`; ниже есть отдельный размер для экранов до 700px.
4. Для замены рисунка подготовь PNG/WebP с настоящей прозрачностью: белый фон или нарисованная шахматка не исчезнут сами; переименование JPG в PNG не конвертирует файл.
   Замени `dragon_100.png` либо добавь новый файл рядом с `index.html`, найди `class="hero-dragon"` и исправь `src`, включая расширение и регистр.
   Увеличь `v=` у картинки; атрибуты `width` и `height` должны соответствовать пропорциям нового исходника.
5. Размер рисунка задаёт `.hero-dragon`: `width: 64px`, в медиазапросе до 700px — `56px`; `height: auto` сохраняет пропорции.
   Для цветной картинки убери инверсию в `[data-theme="dark"] .hero-dragon`: задай `filter: none; mix-blend-mode: normal;`.
   В обычном `.hero-dragon` тоже поставь `mix-blend-mode: normal; opacity: 1;`.
6. Общая шапка с названием сайта и переключателем темы растушёвана: найди `.site-header::before`.
   `filter: blur(16px)` смягчает края, цвет задаётся через `--header-bg` отдельно для каждой темы. Не применяй blur к самой `.site-header`: размоются и кнопки с текстом.
7. Сохрани файлы и проверь обе темы, телефон и прокрутку по пункту 5. Не возвращай большой рекламный блок.

Иконка браузера и превью ссылки обновляются отдельно по пункту 4: замена рисунка рядом с кнопкой их не меняет.

#### 2. Изменить фон

Сейчас фон рисуется кодом, отдельного файла обоев нет.
В `styles.css` открой блок `:root {` для светлой темы или `[data-theme="dark"] {` для тёмной и меняй нужные значения:

| Переменная | Что делает |
|---|---|
| `--canvas` | Основной цвет страницы |
| `--canvas-top`, `--canvas-bottom` | Цвет сверху и снизу |
| `--wash-a`, `--wash-b`, `--wash-c` | Мягкие цветовые пятна |
| `--vignette` | Затемнение краёв |
| `--grain` | Зернистая фактура на странице, карточках и диалогах |

Например, для ровного светлого фона замени значения этих строк **внутри `:root`**, а не добавляй второй блок в конец файла:

```css
--canvas: #f3eee4;
--canvas-top: #f3eee4;
--canvas-bottom: #f3eee4;
--wash-a: transparent;
--wash-b: transparent;
--wash-c: transparent;
--vignette: transparent;
--grain: none;
```

Тёмная тема при этом сохранит свои настройки. Если нужен ровный тёмный фон, сделай то же в `[data-theme="dark"]`,
но для трёх `--canvas*` возьми тёмный цвет, например `#181818`.
`--grain: none` убирает фактуру **также с карточек**; чтобы сохранить её, не меняй эту строку.
Если поменял `--canvas`, синхронизируй цвет панели браузера по пункту 3 ниже.

**Если всё-таки захочешь снова поставить фотографию:**

1. Добавь своё изображение в корень сайта, например `background.webp` — сейчас такого файла нет.
   Экспортируй в настоящий WebP или используй своё расширение; выбирай имя без пробелов.
2. В `styles.css` найди `body::before {`. Внутри него замени только объявление от `background:` до завершающей `;`
   (там сейчас несколько `radial-gradient` и один `linear-gradient`) на:

   ```css
   background: var(--canvas) url("./background.webp?v=1") center / cover no-repeat;
   ```

   Остальные строки `body::before` оставь. `cover` заполняет экран, поэтому края фотографии могут обрезаться, особенно на телефоне.
3. Чтобы видеть фото без зерна, найди существующее правило `body::after { ... }` вне медиазапросов и замени его целиком на:

   ```css
   body::after { display: none; }
   ```

   Фактура карточек останется. Палитра карточек и текста сама под фото не подбирается.
4. По умолчанию эта фотография будет одинаковой в обеих темах — тёмная тема не затемняет её автоматически.
   Если нужен отдельный тёмный вариант, добавь его, например `background-dark.webp`, и сразу после блока `body::before` вставь:

   ```css
   [data-theme="dark"] body::before { background-image: url("./background-dark.webp?v=1"); }
   ```

   Эта строка нужна только если такой файл действительно добавлен. Остальные свойства фона наследуются из общего правила.
5. Увеличь версию CSS в `index.html` по пункту 5 ниже. При последующей замене фото увеличивай также `v=` у его URL в CSS.
   Проверь обе темы и телефон. Если текст плохо читается, выбери более спокойное фото или попроси ИИ адаптировать палитру.

Для возврата к нынешнему CSS-фону восстанови сохранённые `body::before` и `body::after`, убери отдельное правило фото для тёмной темы,
затем отключённые картинки можно удалить из репозитория.

#### 3. Изменить цветовую схему

В `styles.css` светлая тема находится в `:root`, тёмная — в `[data-theme="dark"]`.
Одинаковые имена переменных в этих двух блоках — нормально: у каждой темы свои значения.
**Меняй значения только внутри нужного блока, не делай «Заменить всё» по всему файлу.**

| Что перекрашиваешь | Что искать через Ctrl+F |
|---|---|
| Основную кнопку и её наведение | `--primary`, `--primary-hover` |
| Текст основной кнопки | `--on-primary` |
| Ссылки и акценты | `--accent`, `--accent-strong` |
| Фон и текст акцентных бейджей | `--accent-soft`, `--accent-chip-text` |
| Обводку при переходе клавишей Tab | `--focus` |
| Карточки и их наведение | `--surface`, `--surface-solid`, `--surface-hover` |
| Шапку | `--header-bg` |
| Основной и второстепенный текст | `--text`, `--ink`, `--ink-soft`, `--muted`, `--faint` |
| Полоса прокрутки и теги | `--line-strong`, `--chip`, `--chip-hover` |
| Поля ввода и окно анкеты | `--input`, `--dialog` |

`#b43e32` — пример HEX-цвета; меняй код, сохраняя `#` и точку с запятой.
В записи `rgba(248, 243, 232, .94)` первые три числа — цвет, последнее — непрозрачность: `1` полностью непрозрачно, `0` полностью прозрачно.
Не делай текст и поверхность одинаковыми. `--paper` в тёмной теме намеренно тёмный: это текст на светлых активных вкладках и других выбранных элементах.

**Две детали, которые легко пропустить:**

- Декоративного подчёркивания заголовка больше нет. Если меняешь красный акцент целиком, проверь также цветную тень кнопки `--add-shadow` и пятно фона `--wash-a`.
- Цвет панели браузера задаётся отдельно. Если поменял `--canvas`, в `index.html` найди `name="theme-color"`
  и поставь в `content` новый **светлый** цвет. В `app.js` найди функцию `applyTheme` и строку:

  ```js
  if (themeMeta) themeMeta.content = theme === 'dark' ? '#16130e' : '#ece0c8';
  ```

  Здесь первый цвет — новый тёмный `--canvas`, второй — новый светлый `--canvas`; остальную логику не меняй.
  После изменения `app.js` увеличь и его версию подключения в `index.html`.

Для полной смены палитры проще дать ИИ пример желаемых цветов: нужно согласовать ещё статусы, иконки, тени и читаемость в двух темах.
Для обычного переключения темы код вообще не нужен — нажми луну/солнце справа в шапке; выбор сохраняется в этом браузере.

#### 4. Обновить иконку вкладки и превью ссылки

- `favicon.png` — отдельная квадратная иконка. Если символ сайта меняется целиком, подготовь новую PNG-иконку, например 64×64,
  замени файл и увеличь `v=` у `favicon.png` в `index.html`.
- `og.png` — готовая картинка **1200×630** для Telegram и других сервисов. Её нужно отдельно собрать в графическом редакторе или попросить ИИ.
  Изменение CSS или `dragon_100.png` не обновляет уже нарисованное превью; автоматического генератора в репозитории нет.
- Если сохраняешь имя `og.png` и размер 1200×630, OG-теги менять не нужно.
  При другом имени найди `property="og:image"` и поменяй имя файла в полном адресе, не заменяя адрес на локальный путь.
  При другом размере обнови также `og:image:width` и `og:image:height`.
- Telegram может показывать старую картинку даже после публикации. После успешного деплоя можно запросить обновление через `@WebpageBot` → **Update preview**;
  кэш Telegram независим от кэша твоего браузера и может обновиться не сразу.

#### 5. Проверить изменения и не застрять со старым кэшем

1. В `index.html` увеличь числа после `?v=` **у тех ресурсов, которые изменил**.
   Сейчас подключения — `styles.css?v=21`, `app.js?v=16`, `favicon.png?v=14`, `dragon_100.png?v=14`.
   Например, после изменения CSS сделай `styles.css?v=22`; впоследствии бери следующее число от фактически указанного.
2. Сохрани файлы. Для локального просмотра открой терминал **в папке `s21_izhevsk`**, где находится `index.html`, и запусти:

   ```bash
   python -m http.server 8000 --bind 127.0.0.1
   ```

   Открой `http://127.0.0.1:8000/index.html`. Сервер работает, пока открыт терминал; остановка — **Ctrl+C**.
   Если `python` не найден, попробуй ту же команду с `py`; если обе команды недоступны — попроси ИИ запустить локальное превью.
   Если порт занят уже запущенным превью, используй его либо другой порт, например 8001, и такой же номер в адресе браузера.
3. Нажми **Ctrl+F5**, переключи обе темы, открой все вкладки и форму анкеты. Проверь единственный заголовок со счётчиком, маленького дракона рядом с кнопкой и мягкие края шапки наверху и при прокрутке: текст читается, все действия доступны и ничего не вылезает за экран.

## 4. Деплой: как правки попадают на сайт

1. Сохрани файлы.
2. В папке проекта: `git add <файлы>` → `git commit -m "что изменил"` → `git push`.
   (Или попроси AI подготовить коммит; пушить без твоей команды он не будет.)
3. GitHub Pages публикует ветку, указанную в **Settings → Pages** (для проекта настроена `main`).
   Push в другую ветку сам по себе не обновит сайт: изменения должны попасть в ветку публикации.
   Статус деплоя смотри в **Actions**; обычно он занимает несколько минут.
4. После успешного деплоя открой сайт и нажми **Ctrl+F5**. Можно добавить новый `?v=` к адресу страницы,
   но это не сбрасывает кэш всех вложенных ресурсов: версии CSS, JS и изображений меняются отдельно в `index.html`.
5. Проверь с телефона тоже. Если видишь старое — проверь статус деплоя и версии подключений по разделу «Дизайн: дракон, фон и цвета».

Деплой и кэш — разные вещи: браузер может временно показывать старые ресурсы даже после успешной публикации.

## 5. Уход за Supabase

- **Пауза.** Free-проект засыпает после 7 дней без запросов. Сайт при этом жив, но каталог пустой
  и показывает «Общий список недоступен». Разбудить: дашборд → проект → **Restore project** (пара минут).
  Любой посетитель сайта сбрасывает счётчик сна, так что при живом трафике паузы не будет.
- **Чтобы не засыпал без трафика:** бесплатный cron на cron-job.org или UptimeRobot раз в 3–5 дней
  дёргает GET-запрос к API (пример команды есть в `instructions_for_ai.md` и в истории переписки).
  Ключ в запросе — публичный, это безопасно.
- **Бэкап.** Раз в месяц: Table Editor → people → **Export → CSV**, сохрани файл вне репозитория.
  Схема базы лежит в `supabase/schema.sql` — её достаточно, чтобы развернуть базу с нуля.
- **Лимиты Free:** 2 активных проекта, 500 МБ базы, пауза при простое. Для каталога на сотни людей хватает с запасом.
- **Ключи.** Publishable-ключ (`sb_publishable_...`) лежит в `config.js` и виден всем — так задумано,
  данные защищает RLS. Secret/service_role ключ не копируй никуда, кроме своего менеджера паролей.
  Если он куда-то утёк — дашборд → Settings → API → сгенерировать новый и обновить везде, где использовал.

## 6. Уход за GitHub

- **Добавить админа-разработчика:** репозиторий → Settings → Collaborators → Add people → ник → роль **Write**.
  Write может пушить в `main`, то есть менять живой сайт. Давай только тем, кому доверяешь.
- **Чтобы правки шли через ревью:** Settings → Branches → Add branch protection rule → `main` →
  «Require a pull request before merging». На публичном репо бесплатно.
- **Почему репозиторий публичный:** на Free-плане Pages работает только из публичных репо.
  Приватный репо = сайт умрёт. Прятать в коде нечего: секретов там нет.
- **Добавить админа-модератора:** Supabase → имя организации слева вверху → Organization settings → Team →
  Invite member → email → роль **Developer**. Owner не давай: это право удалить проект.

## 7. Аварийные ситуации

| Что видишь | Что делать |
|---|---|
| Каталог пустой + «Общий список недоступен» | 1) Проект на паузе? Restore. 2) Не менял ли код/схему недавно? Сверь колонки. 3) `config.js`: url без `/rest/v1/`, ключ publishable |
| Сайт 404 | Settings → Pages: источник `main` / `(root)`, репо публичный. Подожди пару минут после изменений |
| Анкета не отправляется, «ник занят» | Такой ник уже есть в базе (возможно, pending). Найди строку в Table Editor и реши: одобрить или удалить |
| Автор не может отменить свою заявку | Заявка отправлена до обновления с токенами, либо автор почистил браузер / сменил устройство. Удали строку сам в Table Editor |
| Спам/мусор в каталоге | Удали строки в Table Editor. Массово: фильтр → чекбоксы → Delete. Защита от спама (honeypot/капча) — в планах |
| Кто-то залил чужие персональные данные | Удали строку сразу, свяжись с человеком. В форме есть согласие «публикую свои данные» |
| Утёк secret-ключ | Перевыпусти в Settings → API, проверь, где он использовался. Publishable-ключ перевыпускать не нужно |
| Pages показывает старую версию | Actions: последний деплой зелёный? Открой с `?v=…`. Telegram-превью обновляется через @WebpageBot |

## 8. Передача проекта после выпуска

Цель: проект живёт без тебя, у нового владельца полный доступ, у тебя — ничего обязательного.
Делай по порядку, не пропускай шаги.

### Подготовка (за неделю до передачи)

1. Собери инвентаризацию: список аккаунтов (GitHub, Supabase, почта приглашений, cron-сервис если есть),
   где лежат пароли, кто текущие админы. Положи в менеджер паролей или зашифрованный файл, не в репо.
2. Сделай бэкап: CSV из Table Editor + копия репозитория (`git clone` или ZIP с GitHub).
3. Доведи документацию до актуальности: этот файл, `README.md`, `instructions_for_ai.md`.
4. Реши, куда переезжает проект: личный аккаунт преемника или организация кампуса (например `s21-izhevsk`).
   Организация лучше: адрес не привязан к человеку и переживёт ещё несколько выпусков.

### GitHub

5. Создай организацию (если выбрал её) и добавь преемника как **Owner**.
6. Репозиторий → Settings → General → Danger zone → **Transfer ownership** → организация или аккаунт преемника.
   Pages переедет вместе с репо. История, issues и настройки сохранятся.
7. Если адрес сайта изменился (новый владелец/организация): обнови `og:url` и `og:image` в `index.html`,
   ссылки в `README.md`, и обнови превью в Telegram через `@WebpageBot`.
8. Проверь Pages в новом месте: Settings → Pages → `main` / `(root)`, Enforce HTTPS.
9. Убери себя из Collaborators (если репо ушло в организацию — выйди из организации или останься рядовым участником без прав).

### Supabase

10. Вариант А (проще): Organization settings → Team → пригласи преемника как **Owner**.
    Когда он принял и проверил доступ — там же **Leave team** (уйти можно, только если есть другой Owner).
    Проект остаётся в организации, ничего не переносится.
11. Вариант Б: если проект в твоей личной организации, а нужна другая — Project Settings → General →
    **Transfer project** в целевую организацию (ты должен быть Owner исходной организации и участником целевой;
    активная GitHub-интеграция должна быть отключена). Возможен простой 1–2 минуты.
12. После переноса открой Settings → API и сверь Project URL и publishable-ключ с `config.js`.
    Если что-то изменилось — поправь `config.js` и запуш.
13. Перевыпусти secret-ключ, если он когда-либо покидал твой менеджер паролей.
14. Настрой keep-alive cron на аккаунт преемника, чтобы проект не засыпал.

### Финал

15. Преемник проходит чек-лист сам: одобрил тестовую заявку, запушил тестовую правку, увидел её на сайте,
    открыл сайт с телефона. Только после этого передача считается состоявшейся.
16. Объяви в чатах кампуса новый адрес (если менялся) и новых админов. Обнови контакты в памятке Rocket.Chat и FAQ, если они изменились.
17. Удали свои доступы везде: GitHub collaborators/org, Supabase team, cron-сервисы.
18. Оставь преемнику этот файл и `instructions_for_ai.md` — дальше проект можно вести даже без тебя и без AI.
