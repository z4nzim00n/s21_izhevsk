# Инструкции для AI-ассистента

Этот файл — контекст и правила работы над проектом `s21_izhevsk`. Читай его перед любыми правками.
Владелец проекта — студент Школы 21 (Ижевск), общается по-русски, не профессиональный разработчик.
Объясняй просто, давай пошаговые инструкции. Интерфейс сайта — только русский.

## 1. Что это за проект

Неофициальный студенческий каталог кампуса Школы 21 в Ижевске: анкеты студентов (ник, имя, Telegram,
направление, интересы), правила и FAQ, полезные сайты, чаты, клубы.

- Статический сайт: HTML + CSS + vanilla JS. **Сборки нет**, `package.json` нет, зависимостей нет,
  кроме `supabase-js`, который грузится с CDN как UMD (`window.supabase`).
- Хостинг: GitHub Pages, ветка `main`, корень репозитория. Деплой автоматический после push.
- База: Supabase (Postgres + REST + RLS). Модерация анкет — вручную в Table Editor.
- Без Supabase (пустой `config.js`) сайт работает в локальном режиме на `localStorage`.

Живой адрес: `https://z4nzim00n.github.io/s21_izhevsk/`
Репозиторий: `https://github.com/z4nzim00n/s21_izhevsk`

## 3. Поток данных анкет

1. Форма `#person-form` → валидация → `submitPerson()`.
2. Если Supabase настроен: `insert` в `people` со `status = 'pending'` (дефолт в БД) и `cancel_token`
   (32 hex-символа, `newCancelToken()`). Копия заявки с токеном кладётся в `localStorage` (`keys.pending`)
   и показывается **только автору** с бейджем «на проверке».
3. Админ меняет `status` на `approved` в Table Editor.
4. `loadRemotePeople()` читает только `approved` (так разрешает RLS), `prunePending()` удаляет
   локальные копии, чьи ники уже пришли с сервера.
5. `syncPendingStatus()` после загрузки спрашивает статус каждой локальной заявки с токеном
   (заголовок `x-s21-token`): `rejected` → бейдж «отклонена», строки нет → локальная копия удаляется с тостом.
   Сеть/пауза → запись не трогается.
6. Корзина на карточке pending/rejected → `requestDelete('pending', …)` → `deleteOwnSubmission()`
   (DELETE с токеном) → строка уходит из базы, локальная копия удаляется, ник освобождается.
7. Если Supabase не настроен: анкеты живут только в `localStorage` (`keys.people`), редактируются и удаляются локально.

Важные детали:

- `allPeople()` = локальные pending + remote (или просто local, если Supabase нет).
- Remote записи **нельзя** редактировать/удалять с сайта (кнопки скрыты). Pending с токеном можно отменить и править
  (`updateOwnSubmission`: PATCH по нику с токеном, ник неизменяем, после правки статус снова `pending`).
- Заявки без токена (отправленные до миграции `cancel_token`) отменить нельзя: кнопки нет, статус не синхронизируется.
  Их убирает модератор удалением строки.
- Токен — единственное доказательство авторства без регистрации. Сверяется **внутри RLS-политики** по заголовку
  `x-s21-token`, а не фильтром клиента: иначе любой мог бы удалять чужие pending-строки.
- Все запросы к Supabase обёрнуты в `withTimeout(..., 15000)`, иначе UI висит при недоступной базе.
- Ключи localStorage версионированы: `s21-izhevsk.people.v1`, `s21-izhevsk.people.pending.v1`,
  `s21-izhevsk.pageSize`, `s21-izhevsk.theme` (`light`/`dark`). Меняешь формат данных — поднимай версию ключа.
  Поля `token` и `status` в pending-записи необязательны (старые записи без них валидны), поэтому версия не менялась.

## 4. Где лежит контент

Всё в `app.js`, массивы в начале IIFE:

- `directions` — id → название направления.
- `interestLabels` — id → название интереса. Пикер интересов строится из него автоматически.
- `clubs` — клубы: `{ id, name, interests, description, organizers?, organizersSoon? }`.
  `organizers: [{ name, nick?, role?, telegram? }]` — ник Школы 21 и роль выводятся текстом, тег копируется кликом.
  `organizersSoon: true` без организаторов → строка «Организатор скоро появится».
- `resourceGroups` — блоки вкладки «Полезные сайты»: `{ id, title }`. Порядок групп = порядок секций.
- `resources` — полезные сайты: `{ id, group, title, description, url }`.
  `group` — id из `resourceGroups`. Декоративные иконки и категории удалены и из шаблона, и из данных.
  Список статический: посетители ничего не добавляют.
- `chatGroups` — группы вкладки «Чаты»: `{ id, title }`. Порядок групп = порядок секций и чипсов фильтра.
- `chats` — чаты и боты: `{ id, group, title, url, tag?, description? }`. `group` — id из `chatGroups`.
  `tag` — короткое уточнение под названием без плашки («все части», «общий чат», «архив»…), `description` — описание;
  оба необязательны и скрываются, если пустые. `url: ''` → заглушка «Ссылку добавим позже».
  В группе `bots` ссылка подписана «Открыть бота», в остальных — «Открыть чат».

Тексты правил, памятки Rocket.Chat и FAQ — прямо в `index.html`, секция `#page-rules`
(`.advice-card` и `<details class="faq-item">`). Памятка и FAQ заполнены реальными данными владельца —
не выдумывай факты о кампусе и не меняй формулировки без просьбы.

Шаблоны карточек — `<template>` в конце `index.html`: `person-template`, `club-template`,
`chat-template`, `resource-template`. Рендер клонирует шаблон и заполняет через `textContent`.

## 5. Рецепты типовых задач

### Добавить / удалить полезный сайт
Правь `resources` в `app.js`: `{ id, group, title, description, url }`.
`group` — существующий id из `resourceGroups`; новая группа = ещё один объект в `resourceGroups`
(заголовок секции появится сам). Удаление = убрать объект из массива. Пользовательского добавления нет:
подборку ведёт владелец, поэтому localStorage для ссылок не используется.
URL проходит `safeUrl()`: только `https:`, без логина/пароля в адресе.

### Добавить / удалить чат
Правь `chats` в `app.js`: `{ id, group, title, url }` + при желании `tag` и `description`.
`group` — существующий id из `chatGroups`; новая группа = ещё один объект в `chatGroups`
(чипс фильтра и заголовок секции появятся сами). Удаление = убрать объект. Счётчик — общее число чатов.

### Добавить клуб / организаторов
Правь `clubs`. Интересы клуба (`interests`) должны быть id из `interestLabels` — они выводятся тегами на карточке.
Декоративных иконок и категорий над названием нет; не добавляй для них поля в данные и элементы в шаблон.

### Добавить направление или интерес
1. Добавь id в `directions` / `interestLabels` в `app.js`.
2. **Обязательно** обнови whitelist в `supabase/schema.sql` (check-конstraints `direction` и `interests`)
   и дай владельцу SQL-миграцию для живой базы (`alter table ... drop constraint ...; add constraint ...`).
   Без миграции insert с новым значением упадёт на ограничении БД.

### Изменить FAQ / правила / памятку
Правь `index.html`, секция `#page-rules`. Новый вопрос = ещё один `<details class="faq-item">`
с `<summary>` и `<p>`; список шагов — `<ol class="faq-steps">`, код — `<code>`, ссылки — обычные `<a>`
(стили для них уже есть). Не добавляй JS без необходимости.

### Добавить новую вкладку
1. `index.html`: ссылка в `.main-nav` с `data-page="newpage"` + `<section class="page-section" id="page-newpage" hidden>`.
2. `app.js`: добавь `'newpage'` в массив страниц в `route()` и в объект `titles`.
3. Если нужен рендер данных: массив данных + функция рендера + вызов в конце IIFE (блок инициализации).
4. `styles.css`: выбери подходящую сетку и её адаптивные правила.
   Полезные сайты и чаты: 4 колонки, до 1020px — 3, до 880px — 2, до 700px — 1.
   Клубы: 3 колонки, до 1020px — 2, до 700px — 1.
5. Иконку бери из спрайта или добавь новый `<symbol>`.

### Удалить вкладку / фичу
Обратный порядок: разметка → роутинг → рендер и данные → стили → шаблоны.
После удаления grepни по id/имени по всему проекту, чтобы не осталось мёртвых ссылок.

### Внешний вид: общие правила

Практическая инструкция для владельца — раздел «Дизайн: дракон, фон и цвета» в `instructions_for_admin.md`.
Сейчас используются светлая «бумага и тушь» и тёмная «ночные чернила», без фото-обоев.
Шрифты — Golos Text для интерфейса и Cormorant Garamond для заголовков.
Это текущее оформление, а не запрет на будущий редизайн: по явной просьбе владельца можно менять дракона, фон и палитры.
Без такой просьбы не возвращай фото-фон, печать «Иж», иллюстрацию и счётчики в верхнем блоке.
Минимализм: никаких декоративных рамок и «бровей» над заголовками, повторов названия кампуса и футера.
Название «Ижевский кампус» видно только в бренде слева в шапке; метаданные и заголовок вкладки браузера остаются информативными.
На первой вкладке сверху только заголовок и кнопка, ниже «Студенты» со счётчиком. `#results-summary.sr-only` сохранён только для экранных читалок: загрузка, результаты поиска, страницы; не возвращай видимый второй счётчик.
Карточка «Официальные правила школы» (`.official-card`) без рисунка книги, надписи «Официальный ресурс» и затемнения; отдельный бейдж FAQ удалён.
В карточках сайтов нет иконок и категорий, в чатах — значка Telegram, в клубах — иконок и категорий над названием.
Клубы: один заголовок и три карточки без вводного описания; реальные описания клубов, интересы и организаторы остаются.
Сетки чатов и полезных сайтов одинаковые: 4/3/2/1 колонки и общие компактные стили `:is(.resources-grid, .chats-grid)`, отступ карточки 18px.
`outline` для клавиатурного фокуса и ошибок, статусы модерации и рамки внутри `forced-colors` — функциональные исключения, их не удаляй.
В форме убрана только фраза «Вводи без @.» у школьного ника; валидация и фиксированный префикс Telegram не меняются.
Номер версии не показывается; технические `?v=` у ресурсов для обновления кэша сохраняются.
Анимаций нет, кроме наведения кнопки «Добавить анкету» в герое (`.hero-actions [data-add-person]`): подъём, тень и блик.
`prefers-reduced-motion` отключает и её. Не добавляй другие анимации, переходы, подсветку курсора или появление карточек.
Для изменения оформления не нужны правки Supabase, RLS, форм или данных контента.

### Дракон и компактная шапка студентов

- `.hero` содержит только `#people-heading` и `.hero-actions` с кнопкой `[data-add-person]`. Это компактная flex-строка с переносом, без отдельной поверхности и иллюстрации.
- Подключения `.hero-dragon`, её фильтров и мобильных размеров больше нет. `dragon_100.png` сохранён как исходник для иконки и превью; его замена сама по себе ничего на странице не меняет.
- Не возвращай рисунок без явной просьбы. При новом запросе используй предоставленный владельцем файл и согласованное место, не восстанавливай старый большой блок целиком.
- Для нового рисунка нужен настоящий PNG/WebP с альфа-каналом, а не белый фон или нарисованная шахматка. Сохраняй пропорции через `height: auto`, проверяй обе темы и телефон; не инвертируй цветные изображения автоматически.
- `favicon.png` и `og.png` обновляются отдельно: ни CSS, ни замена исходника их не перерисовывают.
- Резервные копии держи вне репозитория; исходник удаляй только по согласованной просьбе после проверки ссылок.

### Изменить фон

- Основной фон — `body::before` в `styles.css`: `--canvas-top/--canvas/--canvas-bottom` задают базовый градиент,
  `--wash-a/b/c` — три цветовые размывки, `--vignette` — затемнение краёв.
- `body::after` добавляет зерно `--grain`; `--grain-blend` равен `multiply` в светлой теме и `screen` в тёмной.
- Значения задаются отдельно в `:root` и `[data-theme="dark"]`. Меняй эти блоки, а не добавляй конкурирующие переопределения в конец файла.
- Для однотонного фона в нужной теме уравняй три `--canvas*`, задай `transparent` для `--wash-a/b/c` и `--vignette`.
  Для гладких поверхностей без зерна поставь `--grain: none` (это уберёт зерно и с карточек/диалогов).
- Карточки используют `--surface`; компактный верхний блок не имеет отдельного фона. Старый токен `--overlay` удалён.
- Только по просьбе владельца подключай фото: локальный файл, относительный URL от `styles.css`, например `./background.webp?v=1`.
  Это пример нового имени, такого файла сейчас в репозитории нет.
  Замени только `background` внутри `body::before`, сохрани позиционирование, слои, `pointer-events` и правила `forced-colors`.
  `cover` обрезает изображение под размер экрана; отдельно проверь телефон и обе темы. Если нужна тёмная версия, явно задай её URL или затемняющий слой.
- Просьба «как есть» означает без новых градиентов поверх фотографии и без фонового зерна: отключи `body::after`, не меняя поверхность карточек без просьбы.

### Изменить цветовые схемы

Светлая палитра — `:root`, тёмная — `[data-theme="dark"]` в `styles.css`. Не заменяй все совпадающие HEX-коды глобально.

| Что меняется | Токены |
|---|---|
| Фон страницы | `--canvas`, `--canvas-top`, `--canvas-bottom`, `--wash-a/b/c`, `--vignette` |
| Карточки, шапка, формы | `--surface`, `--surface-solid`, `--surface-hover`, `--header-bg`, `--input`, `--dialog` |
| Текст | `--text`, `--ink`, `--ink-soft`, `--muted`, `--faint` |
| Основная кнопка | `--primary`, `--primary-hover`, `--on-primary`, `--add-shadow` |
| Акценты, ссылки, бейджи, фокус | `--accent`, `--accent-strong`, `--accent-soft`, `--accent-chip-text`, `--focus` |
| Полоса прокрутки, теги | `--line-strong`, `--chip`, `--chip-hover` |
| Статусы и контакты | `--warning-bg`, `--warning-text`, `--danger`, `--danger-bg`, `--danger-hover`, `--info`, `--info-hover` |
| Тени и затемнение диалогов | `--shadow`, `--card-shadow`, `--hover-shadow`, `--backdrop` |

`--paper` используется как текст на инверсных элементах (активные вкладки, тост, выбранные интересы):
в тёмной теме он намеренно тёмный, потому что `--ink` там светлый.
Сохраняй читаемость этих пар и цветовых статусов; проверяй контраст обычного текста не ниже 4.5:1.

Зависимости вне обычных HEX-токенов:

- Декоративное подчёркивание заголовка и `--brush` удалены. Для смены акцента учитывай также цветную тень `--add-shadow` и пятно `--wash-a`.
- При изменении базовых `--canvas` синхронизируй `<meta name="theme-color">` в `index.html` со светлым цветом
  и оба цвета в `applyTheme()` в `app.js` (сейчас тёмный `#16130e`, светлый `#ece0c8`). Затем обнови версию подключения JS.
- Сохрани `#theme-toggle`, ранний скрипт в `<head>` и ключ `s21-izhevsk.theme` (`light`/`dark`).
  По умолчанию тема светлая, системная тема автоматически не выбирается; событие `storage` синхронизирует выбор между вкладками.
  Для теста новой сессии используй изолированный профиль; не очищай всё хранилище владельца ради переключения темы.

## 6. Конвенции кода

- Vanilla JS, один IIFE, `'use strict'`. Без фреймворков, без сборки, без новых зависимостей.
- DOM-хелперы `$` / `$$`. Иконки — `svgIcon(id)` из спрайта.
- **Любой пользовательский ввод вставляется только через `textContent` / `replaceChildren`.**
  Никакого `innerHTML` с данными — защита от XSS.
- Ссылки — только через `safeUrl()`. Telegram-username — через `parseTelegram()` и `telegramPattern`.
- Валидация записей: `validPersonRecord`, `validInterests`, `validDirection`. Косметические поля
  не должны инвалидировать запись целиком (урок истории с аватарками).
- Комментарии — только там, где неочевидно «почему». По умолчанию без комментариев.
- UI-тексты — русский, спокойный нейтральный тон, без сленга, фамильярности, рекламных слоганов и эмодзи.
- Ник показывается **без** `@`, Telegram — **с** `@` (в форме фиксированный префикс `@`, ввод без него).

## 7. Supabase: правила и грабли

- `config.js`: только `url` вида `https://<ref>.supabase.co` (**без** `/rest/v1/`) и publishable-ключ
  (`sb_publishable_...`). `secret` / `service_role` ключ **никогда** не попадает в сайт, репозиторий или чат.
- RLS: anon читает `approved` плюс свою строку по токену из заголовка `x-s21-token`, вставляет только `pending`,
  удаляет и меняет только свою строку со `status <> 'approved'` по тому же токену; update возвращает строку в `pending`.
  Триггер `people_edit_guard` запрещает anon менять `nick`, `created_at`, `cancel_token` (модерацию из дашборда не трогает).
  Не ослабляй политики ради удобства и не переноси проверку токена в фильтр клиента.
- `cancel_token text not null default replace(gen_random_uuid()::text, '-', '')`. При миграции существующие строки
  получают случайные токены: их авторы отменить заявку не смогут (токена нет в их localStorage) — это ожидаемо.
- Статусы: `pending / approved / rejected`. Слово `approved` владелец оставил осознанно — не переименовывай.
- **Миграции схемы делаются ДО деплоя кода.** Список колонок в `.select(...)` должен совпадать с реальной
  таблицей: лишняя колонка в select → 400 → каталог пустой и тост «Общий список недоступен».
- **Грабли UI:** поле «Default value» в Table Editor сохраняет введённое как литеральный текст.
  `''::text` — это то, как UI *показывает* дефолт, вводить это нельзя (получится строка `''::text`).
- Free-план: проект засыпает после 7 дней без активности. Любой запрос к API (в т.ч. открытие сайта)
  сбрасывает счётчик. Разбудить можно только из дашборда (Restore project).
- Модерация — мышкой в Table Editor. Владелец не хочет SQL-консоль для рутинных операций;
  SQL допустим только для разовых миграций, и тогда дай готовую строку целиком.
- В живой базе может остаться неиспользуемая колонка `avatar` (фичу аватарок удалили). Не читай и не пиши её.

## 8. Проверка изменений

1. Локально: `python -m http.server 8000 --bind 127.0.0.1` в папке проекта, открыть `http://127.0.0.1:8000/index.html`.
   Обнови версии изменённых ресурсов в `index.html`, используй жёсткую перезагрузку или отключи кэш в инструментах разработчика.
   Query-параметр у страницы не меняет URL её CSS/JS/картинок. Не очищай пользовательское хранилище с заявками.
2. Прогони сценарий руками или через браузер-автоматизацию: нужная вкладка, форма, диалоги, фильтр, пагинация.
   Обычный локальный сервер с действующим `config.js` всё ещё использует живую базу; тестовые записи допускаются только на изолированном локальном/мок-стенде.
3. Проверь консоль на ошибки и ответы API (200, а не 400/401); не меняй живую базу ради проверки.
4. Для визуальных правок проверь обе темы и узкие экраны: карточки в одну колонку, табы не ломаются, модалки влезают.
5. После push владельцем в ветку публикации дождись успешного Pages-деплоя в Actions, затем проверь живой сайт.
6. После смены OG-превью объясни владельцу независимый кэш Telegram и возможность обновления через `@WebpageBot` → Update preview.

## 10. Осознанные решения (не «чини» их без просьбы)

- Аватарки (пикер и квадраты с инициалами) **удалены** по просьбе владельца: «смотрятся убого». Не возвращай.
- Печать «Иж», дракон и большой рекламный блок **удалены** из интерфейса по просьбе владельца. Сверху только «Студенты кампуса» и кнопка; не возвращай прежнее оформление.
- Текущий фон — CSS-слои в `body::before/::after`, старые фото-обои удалены. Тёмная тема добавлена по просьбе владельца (переключатель в шапке, дефолт — светлая). Без новой явной просьбы не возвращай фото-фон и не убирай переключатель; по просьбе изменить оформление следуй рецептам раздела 5.
- Поля `icon`, `color`, `category` у клубов и ресурсов удалены вместе с декоративными элементами. Полезные уточнения чатов (`tag`) выводятся обычным текстом под названием.
- Регистрации и auth нет. Админка на сайте — возможная будущая фича (Supabase Auth + таблица admins + RLS на update).
- Футер целиком удалён по явной просьбе владельца; старое требование об обязательном футере отменено. Согласие на публикацию в форме сохраняется.
- FAQ, памятка Rocket.Chat и чаты заполнены данными владельца. Организаторы клубов заполнены частично (теннис ждёт организатора). Чатов у клубов не будет — не выдумывай «правдоподобные» факты о кампусе.

## 11. Быстрая диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| Каталог пустой, тост «Общий список недоступен» | 400 от REST (лишняя колонка в select), пауза проекта, неверный url/ключ | Сверь select со схемой, статус проекта в дашборде, `config.js` |
| На одном устройстве люди есть, на другом нет | Локальные pending-копии в localStorage vs пустой/сломанный remote | Починить remote; локальные копии сами исчезнут через `prunePending` |
| Анкета не отправляется | Ограничение БД (ник занят `23505`, whitelist direction/interests), пауза | Текст ошибки в форме; миграция или модерация |
| «Не удалось отменить заявку» | Пауза проекта, сеть, либо строка уже удалена и токен не совпал | Повторить; если строки нет — локальная копия уйдёт при следующей загрузке через `syncPendingStatus` |
| Локальные заявки пропали после обновления кода | `validPersonRecord` отверг запись (например, пустой `token` у старой записи) и `loadRecords` сбросил массив | Проверять валидатор на старых записях без новых полей; пустой токен должен быть валиден |
| Сайт 404 на Pages | Pages выключен/не та ветка/репо приватный на Free | Settings → Pages; репо должен быть публичным на Free |
| Старая вёрстка после правок | Кэш браузера/bfcache | Cache-bust query, жёсткая перезагрузка |
| Превью в Telegram старое | Кэш Telegram | `@WebpageBot` → Update preview |
